# 恋愛ゲームを楽しみながら相性を探る：実装タスク

2026-11-07。設計段階。以下は未実装の計画で、既存機能の完了記録とは区別する。

## 目的と最初の完成単位

Miraとの出来事を楽しみ、自分の希望を伝えながら、共通点・違い・違いへの向き合い方を知る。親しくなることと相性が合うことを別々に扱う。

最初の完成単位は「第1話 → 保存 → アプリを再起動 → 第2話の再会 → 前回の返答に応じた行動 → 根拠付きの振り返り」。まずこの範囲を実際に遊べる状態にする。その後、第2話の残りと第3話を完成させる。

- 対象は架空の成人Mira。既存の本人Persona作成・実マッチ相手の会話・Ashaは維持する。
- 初回のプロフィール再入力は不要。相性のアンケートを必須の進行条件にしない。
- 各話5〜7分は試遊で確かめる目安。発言数や経過時間で強制終了しない。
- JP/ENを最初から扱う。現行どおり画面の言語指定に新しい応答を合わせる。入力言語の自動判定は今回追加しない。
- 画像は現在のMiraを基準とし、Ashaとの画像割当を保つ。

## 現在のコードから分かったこと

| 既存の仕組み | 今回の扱い |
|---|---|
| `cafe-adventure.ts` の6段階・固定台詞・限定的な自由入力認識 | 新しいエピソード進行を別バージョンで導入。旧セーブに途中から新脚本を混ぜない |
| `conversation-service.ts` のrevision・再送検証・所有権検証 | 再利用し、章と関係の保存にも適用 |
| `reflection.ts` の4観点・双方の引用・未判定・歩み寄りの順序検証 | 再利用し、章をまたぐ根拠参照と解釈取消に拡張 |
| `conversation-llm.ts` の返答・候補・振り返り生成 | 進行候補の解釈と演出を分離し、確定状態を文脈に渡す |
| `store.ts` の会話と本人識別はメモリ上のMap | 永続保存と再開用の識別を一緒に実装する必要がある |
| 会話は最長2時間、本人セッションは8時間 | 「翌日も覚えている」には有効期間と復元の設計変更が必要 |
| `character-art.ts` と会話UI | 現在の顔を維持して表情を追加。出来事・表情を中心に配置 |

## 体験の構成

| 話 | 出来事 | 関係が変わる瞬間 | 相性を探る機会 |
|---|---|---|---|
| 1：雨宿りのカフェ | 写真好きのMiraと話し、雨が止む | 二人だけの冗談／次に会う提案 | 会話のペース、距離の取り方 |
| 2：街の撮影散歩 | Miraに誘われ、寄り道や写真選びをする | 前回の話を覚えている／作品への迷いを見せる | 計画と即興、好みの違い |
| 3：帰り道 | 応募する写真について話す | 本音を共有し、次の約束をする | 話を聞く・助言する希望、違いへの対応 |

Miraの人物設定案：写真が好きで小さな写真展への応募を考えている。冗談や誘いは得意だが、作品を真剣に見てもらうときはためらう。好み・予定・意見を持ち、プレイヤーの発言に無条件に同意しない。この設定はT01で既存設定との整合を確認して確定する。

## タスクと完成条件

### T01 / P0：脚本と相性が見える場面の設計

- [ ] 第1話全体と第2話の再会をJP/ENで書く。第2・3話の出来事と結末も定義する。
- [ ] 各場面に、Miraの目的、発話、表情、プレイヤーの選択、自由入力例、後で返ってくる反応を記載する。
- [ ] 「率直に伝える／冗談を交わす／余地を残す」など各選択に別の意味を持たせる。迎合だけが進展条件にならないようにする。
- [ ] 異なる希望を伝えても次話へ進めるルート、誘いを断って気持ちよく区切れるルートを用意する。
- [ ] 場面ごとに相性の観点と必要な根拠を対応付ける。選択肢自体は診断質問の文面にしない。

完成条件：同じ開始から3種類の接し方で台本を通し、違う反応と再会時の違いを説明できる。各ルートにMiraの個性が見える出来事と自然な区切りがある。

### T02 / P0：物語・関係・相性のデータを分離する

依存：T01。新規候補 `src/lib/romance-story.ts`、`src/lib/relationship.ts`。既存 `conversation.ts` を拡張。

- [ ] `EpisodeState`：脚本バージョン、章、場面、成立した出来事、未解決の話題、完了状態。
- [ ] `RelationshipState`：所有者、安定した相手キー、関係の段階、呼び名、共有した出来事、約束、次に会える章。
- [ ] `MemoryFact`：誰の発言か、内容、根拠の会話ID・発言ID、保存時点、訂正・取消状態。
- [ ] `CompatibilityObservation`：既存のpace / activities / closeness / differences、共通点・違い・歩み寄り・複数の傾向・未判定、双方の根拠。
- [ ] 関係の段階は成立したイベントから更新する。相性の合計点・成功確率・キャラクター順位は作らない。
- [ ] 会話上の行為と物語の行為を識別できる履歴形式にする。発言引用と出来事の記録を区別する。

完成条件：好みが違っても関係が進むケースと、丁寧な返答だけでは相性を判断できないケースを型・状態テストで表現できる。

### T03 / P0：次回まで残る保存と再開

依存：T02。対象 `server/store.ts`、`server/security.ts`、`server/conversation-service.ts`。必要なら専用repositoryを追加。

- [ ] ローカル単一サーバーのデモでは、既存の暗号化方式と原子的ファイル更新を使い、関係・章・必要な会話根拠・再送記録を保存する。
- [ ] デモ用の再開トークンをHttpOnly Cookieとサーバー側の永続レコードで管理する。クライアントが指定するownerIdを所有権として信頼しない。
- [ ] 計画上の保持期限は最終利用から30日。同じブラウザでの復元を対象とし、Cookie削除後や別端末の復元は対象外。設定・表示・期限切れ削除を揃える。
- [ ] 同じ利用者・Miraの関係を、毎回作り直されるデモPersona IDに依存せず識別する。
- [ ] 「続き」「次のデート」「独立した再プレイ」「記録削除」の意味を分ける。再プレイで本編の記憶を二重登録しない。
- [ ] 保存失敗時は成功扱いにせず、再試行でイベントや思い出が重複しないようにする。二つのタブの競合も検出する。
- [ ] 記憶の訂正・削除を後続の生成と振り返りに反映する。根拠が削除された解釈も無効化する。
- [ ] 保存先をGit・配信資産から除外する。実マッチ側の認証・同意確認は維持し、デモの長期識別を本番認証の代わりにしない。

完成条件：サーバー再起動、ブラウザ再読み込み、翌日相当の時刻でも同じ関係を復元できる。別ブラウザからは見えず、期限切れ・削除後には戻らない。

### T04 / P0：返答で自然に進む状態機械

依存：T01・T02。対象 `romance-story.ts`、`server/conversation-service.ts`。

- [ ] 選択肢と自由入力を、同じ「発言＋許可された意図」の処理へつなぐ。
- [ ] まず相手が発言に応じ、出来事の成立条件を満たしたら場面を進める。「次の展開を選ぶ」を常用しない。
- [ ] 質問・保留・否定・話の訂正・休憩を扱う。話を掘り下げているときに回数だけで場面を飛ばさない。
- [ ] 曖昧な行動は勝手に確定せず、その場に合う短い返事と具体的な候補を出す。毎回の確認質問にはしない。
- [ ] 章が終わったら短い余韻と次の導線を出す。自由会話は任意で続けられ、完了済みイベントは再発火しない。
- [ ] 古い候補、revision、clientTurnIdの検証を継承する。確定した状態と台詞を一つの保存単位として扱う。

完成条件：選択だけ・自由入力だけ・混在の3経路で第1話を終えられる。断りや休憩が意図せず承諾にならず、再送で二重進行しない。

### T05 / P0：LLMの会話・記憶参照・演出

依存：T02・T04。対象 `server/conversation-llm.ts`、Zodスキーマ。

- [ ] 役割を「入力の意図候補 → サーバーが許可された遷移を判定 → 確定した出来事に合う台詞・表情」に分ける。
- [ ] 構造化出力に発言、表情ID、話題継続の意図、参照した記憶IDを持たせる。任意のイベントや記憶を書き込ませない。
- [ ] Miraの設定、現在の場面、最近の会話、今回関係する確定記憶だけを文脈に渡す。
- [ ] プレイヤーが実際に伝えた事実を保存する。冗談・仮定・引用・否定を恒常的な好みに変換しない。
- [ ] 毎回質問で終わらず、反応・自己開示・小さな行動を織り交ぜる。未成立の約束や親密さを作らない。
- [ ] タイムアウト／不正出力にはその場面の短い台詞または再試行を用意する。失敗を相性の評価に使わない。

完成条件：JP/ENで率直・冗談・不同意・脱線・訂正の会話を確認。自由入力でも質問の反復や未来の出来事の捏造を避け、第2話で本当に保存した内容を参照できる。

### T06 / P0：相性の発見と振り返りをゲームに組み込む

依存：T02・T04・T05。対象 `reflection.ts`、`server/conversation-llm.ts`、`conversation-experience.tsx`。

- [ ] 各話の区切りに「共通点」「違い・向き合い方」「まだ分からないこと」を最大3件程度表示する。根拠がなければ埋めない。
- [ ] 既存4観点を維持。支え方はdifferences、距離感はclosenessとして扱い、初回から分類を増やさない。
- [ ] 双方の明示した言葉を照合する。選んだ経路だけで「冒険好き」などの性格を推定しない。
- [ ] 場面が用意した共通体験と、双方が表明した好みの一致を分ける。丁寧さやゲームのクリアを相性の良さに変換しない。
- [ ] 「歩み寄れた」は違い→提案→相手の受諾の時系列がある場合に限る。解釈の妥当性も会話例で確認する。
- [ ] 章をまたぐ根拠はconversationIdとmessageIdで辿れるようにする。取消・訂正・矛盾する根拠も次回に引き継ぐ。
- [ ] 定型デモでも、台本で実際に表明された内容から検証可能な振り返りを出す。自由文を理解できない場合は未判定にする。
- [ ] 「自然体で話せたか」「また会いたいか」の本人の任意回答を、AIの解釈と分けて残す。

完成条件：共通点／違いを尊重／無理に合わせたという本人の感想／根拠不足／発言の訂正を試し、各結果に一致する引用がある。不同意を一律に減点しない。

### T07 / P0：表情と出来事が中心のプレイ画面

依存：T01・T04。対象 `conversation-experience.tsx`、`masala-app.tsx`、`character-art.ts`。新規のシーン表示コンポーネントを検討。

- [ ] 現在のMiraの顔を保ち、通常・笑顔・からかい・照れ・迷いの表情を準備する。既存emotionとの対応を定義する。
- [ ] 立ち絵、背景、短い情景、台詞、返答候補と自由入力を同じ場面にまとめる。
- [ ] 表情は確定した返答と同時に更新し、通信中に先の結果を見せない。画像不足時も台詞で状態が伝わるようにする。
- [ ] 普段は相性分析を閉じ、章の区切りで短く表示する。詳しい引用と履歴は任意で開く。
- [ ] 次話の予告、Miraからの誘い、思い出帳、再開をつなぐ。実時間待機や通知送信は導入しない。
- [ ] JP/EN切替時に入力・関係・記憶を保ち、今後の台詞と候補を切り替える。引用は原文を保つ。
- [ ] モバイル、キーボード、読上げ、動きを減らす設定を確認する。

完成条件：画面から「誰と何をしているか」「何が変わったか」「どう返答するか」が分かる。分析を開かずに遊べる。

### T08 / P0：最初の完成単位を通して検証する

依存：T03〜T07。状態テスト、APIテスト、実LLM会話、ブラウザ試遊を役割分担して実施する。

- [ ] 率直に希望を伝える／冗談で距離を縮める／違う希望を伝える、の3ルートをJP/ENで試す。
- [ ] 第1話→再起動→第2話の再会で、前回に応じた台詞・行動・根拠が一致することを確認する。
- [ ] 保存失敗、二重送信、別タブ、所有権、期限切れ、取消、言語切替をAPIで確認する。
- [ ] 状態テスト、型チェック、ビルド、既存会話・振り返りの回帰確認を行う。対象コードを書く前にローカルのNext.jsガイドを読む。
- [ ] 人の試遊では「気になったMiraの一面」「自分の返答で変わったこと」「合う点・違う点」「次に知りたいこと」を自由に聞き、詰まった場面も記録する。

完成条件：技術的な合格と人による面白さの評価を分けて記録する。Miraに興味が持てない、選択が結果に見えない、相性が分からない場合は、第1話の脚本・反応に戻って修正する。

### T09 / P1：第2・3話を完成させる

依存：T08の試遊結果を反映した後。

- [ ] 撮影散歩と帰り道を実装し、前話の記憶と関係の段階を反映する。
- [ ] 共通点があるルートと違いを尊重するルートの両方に、固有の良い場面を作る。
- [ ] 3話の終わりに、二人の出来事・相性の根拠・未判定を振り返れるようにする。
- [ ] 新しい関係を試す再プレイを本編の履歴から分離する。

完成条件：3話を通して関係が連続し、初回と再会で態度が変わる。本人の望まない恋愛進展を強制せず、それぞれの選択で話がまとまる。

### T10 / P2：Ashaへの展開を検討する

依存：Miraの試遊結果。

- [ ] Asha固有の目的・関心・距離の取り方で別の出来事を書く。
- [ ] 同じ言動に異なる反応があることを、人物設定と根拠で説明できるようにする。
- [ ] 相手間の比較は、同じ観点の根拠と未判定を示す。優劣ランキングにしない。

実マッチ相手へ架空の写真家設定や恋愛感情を流用しない。実マッチへの新体験の適用は別途設計する。
