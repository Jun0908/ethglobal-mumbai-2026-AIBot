# 会話品質修正の実装・検証（2026-11-06）

## 実装した変更

- 相手の返答生成 → 事実整合性の確認・修正文生成 → プレイヤー候補生成 → 候補の意味検査へ分離。毎回の反対意見・質問と2〜4文の強制を撤去。
- 実際に観測した緊張・仕事の失敗・沈黙の発言について、話し手が逆転する候補を補助的な決定的検査でも拒否。JSON断片や出力メモの混入も拒否。
- 候補が不正・生成失敗の場合は短い汎用候補へ退避し、正常な相手の返答を保持する。再生成ループは設けない。
- 自由会話の生成段階は各12秒・自動再試行なし。最大4段階のため、画面の65秒タイムアウト内に収まるよう制限した。APIの通信等の追加時間は別途かかる。
- 香り当ては開始 → 3択回答 → 正誤確定 → 次回の予定の順に進む。回答前に完了しない。回答は通常の会話候補から分離し、結果と参加者をサーバーで保持。出題・正誤・結果の再確認は確定した文章を使用する。
- 香り当ては固定の1問。通常の物語3段階に回答操作が1つ加わることを表示する。全分岐は33経路。
- Asha/Mira別の冒頭を履歴に含め、Miraの初期候補も冒頭の遊び・休憩に対応。再開では冒頭を追加しない。60往復の判定はメッセージ数でなく送信revisionを使用する。
- 固定の架空Personaに具体的な関心・反応例を追加。英語設定もスキーマに適合することを検証。
- JP/EN切り替え時は最新の会話から新しい言語の候補を生成する。会話の取得・再開も送信と同じロックで保護し、古い生成結果による上書きを防ぐ。既存の発話は書き換えない。
- 相性の引用対象から物語の操作と冒頭の固定発話を除外。

- `scripts/check-conversation-quality.mjs`: 中間版と最終の生成処理で各40往復、Asha/Mira × JP/ENを実行。自由入力6件、物語・回答・結果確認4件を各組み合わせで実施。別の初期改修版でも40往復を確認し、不具合を追加修正した。
- 最後の40往復では、映画の未確定回答4/4、ゲームを実際に始める応答4/4、沈黙に質問を返さない応答4/4、ゲーム結果の一致4/4をログで確認。仕事の失敗へのプレイヤー候補でも、本人の失敗を相手の失敗として質問する元の回帰例は見られなかった。

- [最後の40往復の全記録](CONVERSATION_FIX_VERIFICATION_TRANSCRIPT.md) を保存。この記録の後に出題・正誤の文体を直接話す形式に調整し、Miraの冒頭候補を変更した。生成処理自体は変更していない。

## 残る制約

LLMの意味検査は完全ではなく、今回は少数の架空入力による検証。相づちの説明っぽさや、雨・チャイへの話題の戻り、似た候補が出ることは残り得る。不正な候補を避けるための汎用退避では、選択肢の具体性が下がる。今回の結果を自然さ全般の保証とは扱わない。

履歴は従来どおりサーバーのメモリ内に保持する。本番ビルドの再起動で以前の会話は終了する。
