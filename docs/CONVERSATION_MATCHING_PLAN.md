# 会話を楽しみ、相性の理由を知るための改善案

2026-11-06。ユーザーの「もっと会話したい」「Asha / Miraとの相性が分からない」への検討。以下は設計案であり、相性分析はまだ実装していない。

状態・データ・API・実装順の詳細は [会話と相性の実装仕様案](CONVERSATION_IMPLEMENTATION_SPEC.md) を参照。

## 現在の実装で起きていること

- Asha / Miraは固定の架空デモ相手。候補選定、ランキング、ユーザーとの相性計算はない。メイン開始ボタンはAshaを指定する。
- Ashaは静かな会話、Miraは即興や新しい体験を好む設定。LLMには相手のPersona、場面、直近の会話が渡される。プレイヤーが作成したPersonaを比較に使う処理はない。
- `matching.ts`は外部サービスのマッチ当事者・相手Persona・期限・利用同意の検証を行うアダプター。相性算出器ではない。外部サービスの実際の候補選定方法はこのリポジトリから確認できない。
- ゲームは3回の行動で完結。会話は小さな任意リンクの先にあり、行動後に入力欄が閉じる。結末ではUIもAPIも追加会話を受け付けない。
- 結末は行動の振り返りと相手の発言の引用であり、ふたりの相性の説明ではない。

## 画面確認の結果

1. 相手一覧：性格の紹介はあるが、推薦理由・比較・まだ未判定である説明がない。2名の絵も共通で、人物差を捉えにくい。
2. デート：場面と進行は明確になった。一方で行動ボタンが中心で、会話の入口は弱い。プレイヤーに「もっと話す」より「次へ進む」を促す構成になっている。

この2画面を現行ローカル環境で撮影・確認した。終盤の会話拒否は今回のコード確認によるもの。今回は結末までの新たな実LLM通し操作、キーボード・読み上げ・コントラストの測定は行っていない。小さい会話リンクの発見しやすさは改善対象だが、スクリーンショットだけでアクセシビリティ準拠は判定しない。

## 目指す体験

目標は「自分らしく話した上で、どの相手と、どんな過ごし方なら心地よいかを自分で選べる」こと。

会話量を増やすだけでは、以前の終わらない質問に戻る。物語の進行と会話の終了を分け、節目と出口を保ちながら話し続けられるようにする。

### 会話を中心にした1回のデート

- 最初から相手の発言、会話履歴、入力欄を表示する。
- 文章を考えなくても参加できる短い返答候補を3つ表示する。押すと発言として送信する。「その他」で自由入力に切り替えられる。
- 「会話の返答」と「次の場所へ進む」を、文言と配置で区別する。同じ選択UIで発言と場面移動を混在させない。
- キャラクターは相手の発言に反応し、自分の好みを少し話し、ときどき問い返す。毎回質問を追加しない。好みに違いがあるときは自然に表現し、プレイヤーの意見に無条件で同調しない。
- 場面は、出会い → 小さな違い → ふたりで折り合いを探す、という3つの節目を用意する。現在の雨の分岐は、その中の出来事として再利用できる。
- 各場面で2〜4往復を目安に「次へ進む」を提案する。これは設計上の初期目安であり、最低入力数や強制終了条件にはしない。いつでも振り返りへ進める。
- 物語が終わっても「このまま話す」「相性を振り返る」「別の相手と話す」を選べる。再挑戦するまで会話を失わない。

### 面白さを作る具体例

プレイヤーが「雨でも市場へ行きたい」と話した場合、Ashaは「人混みは少し苦手。でも屋根のある通りを少しなら」と返し、Miraは「寄り道して面白いお店を見つけよう」と返す。

これは提案用の台詞例であり、実際に生成された会話ではない。Ashaへの正解を当てるゲームにはしない。プレイヤーが自分の希望を伝え、ふたりで調整する過程を見せる。静かな人と活発な人でも、心地よい折り合いを見つける展開を成立させる。

## 相性は根拠を見せる

「相性87%」のような恋愛成功確率は作らない。最初は次の4観点について、今回の会話で見えたことを表示する。

| 観点 | 見ること | 結論を出さない場合 |
| --- | --- | --- |
| 会話のペース | ゆっくり話したい、沈黙も心地よい、テンポよく話したい等の明示された好みと応答 | 短文・返信速度だけから推定しない |
| 過ごし方 | 静かな時間、新しい体験などの好みと双方の反応 | 1回のゲーム上の行動だけで恒常的な性格にしない |
| 距離の縮め方 | 少しずつ知りたい、質問の多さ、冗談などの好み | 発言がない観点は未確認 |
| 違いへの向き合い方 | 希望の違いを伝え、理由を聞き、代案を探したやり取り | 違いを経験していないなら未確認 |

各観点の表示は「合う傾向」「違いが見えた」「歩み寄れた」「まだ分からない」。違いがあることを相性の悪さと同一視しない。

1件の説明には、プレイヤーの発言 → 相手の返答 → 解釈 → まだ分からない点、を含める。根拠の会話へ戻れるようにする。引用は実在するメッセージだけを使用する。

例：「あなたは静かな場所が好きと話し、Ashaも落ち着ける場所を希望しました。過ごし方には共通点が見えます。ただし意見が違う場面はまだありません。」これは表示形式の例で、現在のユーザーの診断ではない。

本人の感覚も別に残す。任意の「自然体で話せた／少し気を使った／まだ分からない」と「また話したい」を用意する。AIの解釈と本人の感想が違う場合は、両者を表示し、ユーザーが訂正できるようにする。感想の回答を会話再開の必須条件にしない。

## AshaとMiraをどう比較するか

- 会話前：候補は「体験できる2人」と明記する。まだ相性で選定していない状態を説明する。
- 既に承認済みの自分のPersonaがある場合：再質問せず、利用範囲内の会話傾向から「共通点の仮説」を示す。実際に話した結果とは別に表示する。
- 自分のAIを作っていない場合：そのまま話せる。今回の発言と任意の本人の感想から徐々に情報を集める。
- 片方だけと話した場合：もう片方は「未会話」。自動で優劣を付けない。
- 両方と話した場合：同じ4観点で並べ、根拠と情報量の差を示す。「Ashaとは静かに話せた」「Miraとは新しい体験の話が弾んだ」のように、合い方の違いを伝える。
- 相手の人物像は異なる肖像・話し方・反応で区別する。単に片方を高得点にする設計にしない。

外部PSIサービスによる候補選定と、今回の会話を振り返る相性分析は別レイヤー。外部連携時の推薦理由は、そのサービスが公開を許可する根拠だけを表示する。PSIの利用だけで恋愛相性や成功確率を保証しない。

## 実装する順番

1. 会話の主画面化と終了状態の分離。`storyCompleted`と会話を閉じた状態を区別する。任意の振り返り、終了後の会話継続、既存の行動分岐を両立させる。
2. メッセージにIDと種別（自由発言、返答候補、場面移動）を付ける。場面移動を本人の価値観の発言と混同しない。LLMの記憶は直近履歴と根拠付き要約を使い、長い会話でも矛盾を抑える。
3. 会話の根拠に結び付いた振り返りを追加する。LLMは候補の抽出と説明を担当し、サーバーがメッセージID、引用、参照範囲、入力不足を検証する。検証できなければ「まだ分からない」を返す。
4. Asha / Miraとのセッションを個別に保持し、同じ観点の比較画面を追加する。人物の見た目も区別する。

分析にはこの本人が閲覧できる会話と公開可能な情報だけを使う。非公開Personaの内部項目をそのまま診断根拠として表示しない。JP/ENは既存の選択に追従し、原文引用は原文と分かる形で残す。

## 受け入れ条件

- 自分のAIの再作成や個人情報の再確認なしで会話できる。
- 選択式だけでも、自由入力だけでも、途中で切り替えても会話できる。
- 場面を変えずに会話を続けられ、物語終了後も会話できる。
- 会話の区切りと次の行動が分かり、いつでも振り返りや終了を選べる。
- 相性の説明から実際の根拠を確認でき、ない発言・本人の感情・実人物の同意を捏造しない。
- 片方が未会話、回答不足、矛盾した証拠の場合に安易な順位を出さない。
- Asha / Miraは性格の違いを保ち、プレイヤーが常に相手へ合わせなくても自然な対話になる。
- JP/EN、入力保持、長い会話の記憶、同意撤回、所有権、会話継続後の申請重複防止を確認する。

実装後は、ユーザーが会話を続けられたか、相性の説明を自分の言葉で理解できたか、どちらとまた話したいかを理由付きで選べたかを確かめる。会話ターン数の増加だけを成功と扱わない。
